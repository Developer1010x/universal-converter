================================================================================
WHAT IT IS
================================================================================

A file-conversion library where the converters form a graph rather than a
lookup table. 198 format pairs are implemented directly. Another 234 are
reached by chaining converters via breadth-first search over the registry's
adjacency map, so `csv -> pdf` works without anyone implementing it:

    $ universal-convert cities.csv -t pdf
    converted cities.pdf  via csv -> html -> pdf

That routing is the reason this exists. Single-hop conversion is already owned
by pandoc, ffmpeg and Pillow; automatic multi-hop planning over a plugin
registry is not.

================================================================================
ARCHITECTURE
================================================================================

1. REGISTRY-DRIVEN DISPATCH
   pkgutil walks converters/, collects every concrete BaseConverter subclass,
   and caches the result. PRIORITY orders competitors - lower wins - so
   ImageConverter (10) beats the generic DataConverter (50) on a shared pair.
   Nothing in the CLI or the public API names a converter class.

2. MULTI-HOP ROUTING
   supported_conversions() returns {source: [targets]}, which is an adjacency
   list. find_route() BFSes it, so the first path found has the fewest hops.
   Intermediates go to a TemporaryDirectory; only the last step writes to the
   destination. Routing skips edges whose dependencies are missing.

3. LAZY OPTIONAL DEPENDENCIES
   Every optional import sits inside a method. Importing the package, or the
   registry, pulls in nothing heavy. A missing package therefore shortens what
   --doctor reports as ready, never what --list advertises.

4. HONEST CAPABILITY REPORTING
   --doctor checks each pair's Python imports and external binaries, and prints
   how many pairs each missing package would unlock. A test walks the whole
   registry and fails if any advertised pair answers "unsupported".

================================================================================
DEPENDENCIES
================================================================================

Core: none.

Optional, one group per capability, every package imported by code in src/:
  data   PyYAML                     toml   tomli-w (+ tomli on <3.11)
  images Pillow                     docx   python-docx
  pdf    pypdf, reportlab           xlsx   openpyxl
  torch  torch, onnx (excluded from [all]: multi-gigabyte download)

External: the ffmpeg binary unlocks 72 audio/video pairs. It is a system
package; pip cannot install it, and the error messages say so.

================================================================================
CHANGES IN 1.1.0
================================================================================

Fixed
  - All 72 audio/video pairs raised TypeError: run_command returns a
    CompletedProcess and every media call site subscripted it as a dict.
    ffprobe output was bytes, so json.loads could never have worked either.
  - The CLI hardcoded DataConverter, making 10 converter classes unreachable;
    a PNG was routed through the JSON/CSV text converter.
  - PRIORITY sorted descending while specialists used low numbers, so
    find_converter('tiff','png') returned GISConverter, not ImageConverter.
  - resize_image()/thumbnail() defaulted the output to the input path and
    destroyed the source file.
  - CSV was written by joining values with a comma - no quoting, no escaping -
    and column names were taken from the first record only.
  - SQLite -> SQL emitted column names with no types and unescaped literals.
  - torch.load(weights_only=False) executed arbitrary code from any .pt file.
  - The README's headline example raised ImportError.

Removed (advertised without an implementation)
  - 33 pairs: bam/cram/sam/bcf/bigbed, h5/tflite model formats, shapefiles.
  - PDBConverter, which unconditionally returned failure.
  - 4 no-op alias subclasses that registered as duplicate converters.
  - 20 of 24 optional-dependency groups: 51 of 55 declared packages were
    imported nowhere.

Added
  - Multi-hop BFS routing with --route, and automatic chaining on conversion.
  - --doctor capability audit.
  - Registry-driven dispatch, --from/--to overrides, --direct, exit codes.
  - tests/ (78 tests) and a CI job that runs them on 3.9-3.13.
